# 데일리 노트 — 2026.07.28

## 오늘 요약 (공유용)

지도를 Kakao Maps에서 Naver Maps로 통째로 갈아엎은 날. 발단은 답사 예정 지역(강화군 하도리) 카카오 로드뷰가 2020년에 멈춰 있어 최근 생긴 도로가 안 보인다는 문제였고, 네이버 로드뷰는 2024년 기준이라 전환을 결정했다. 네이버클라우드플랫폼(NCP) 신규 지도 상품('Maps')의 무료 이용량 정책을 확인하는 과정에서 한 번 잘못된 정보(무료 종료)를 짚었다가 정정했고, 실제 계정 가입 단계에서는 회사 IP가 "다수 계정 생성" 차단에 걸려 한참 헤맸다(결국 아이패드로 우회 가입 성공). 이후 지도 컴포넌트 5개 파일 + 서버 지오코딩 라우트 2개를 전부 이식하는 코드 작업을 진행해 완료했고, 마지막으로 실제 확인 중 "네이버 기본 지도 스타일엔 버스정류장 아이콘이 없다"는 한계를 발견했다(코드로 해결 불가한 API 자체 제약으로 판단, 패스하기로 함).

## 오늘 한 일

### 1. Kakao → Naver 전환 의사결정
- 카카오 로드뷰(2020)와 네이버 로드뷰(2024) 최신성 격차를 실제 답사 지역 스크린샷으로 확인 후 전환 결정
- NCP 지도 API 비용 조사 과정에서 시행착오: 처음엔 "구 AI NAVER API의 무료 이용량이 2025-07-01 종료"라는 정보만 보고 무료가 아니라고 잘못 안내했다가, 사용자가 공식 공지를 직접 붙여준 뒤 "2025-03-20 출시된 신상품 'Maps'는 무료 이용량이 그대로 제공된다"는 걸 확인하고 정정
- 신상품 'Maps'의 무료 이용량(API별 월 3,000~600만 건, 대표 계정 기준) 확인 — 이 행사 규모에서는 비용 문제 없음

### 2. NCP 계정 가입 트러블슈팅 (커밋 없음, 진행 지원)
- 일반 네이버 아이디 가입 화면에서 "동일 IP 다수 계정 생성 불가" 팝업에 막힘 — 회사 네트워크(고정 IP로 추정, ISP "Dacom Corp")에서 이미 여러 명이 가입한 이력 때문으로 추정
- 와이파이를 여러 번 바꿔도 "내 아이피" 조회 결과가 그대로였음(회사 고정 회선으로 추정) → 결국 아이패드(별도 네트워크)로 전환해 가입 성공
- 사업자등록증으로 우회하면 바로 뚫린다는 걸 발견했으나, 회사 업무와 무관한 개인 프로젝트에 회사 명의를 쓰는 리스크(약관 오남용, 결제 책임 귀속, 신뢰 문제)를 짚어 개인 명의 유지로 방향 잡음
- NCP Maps 콘솔에서 Application 등록(Dynamic Map + Geocoding + Reverse Geocoding API 선택, Web 서비스 URL에 로컬(`localhost:4000`)/배포 도메인 등록) 안내

### 3. 지도 SDK 코드 마이그레이션 (미커밋 — 이 노트와 함께 커밋)
- `.env.example`: `NEXT_PUBLIC_KAKAO_JS_KEY` → `NEXT_PUBLIC_NAVER_MAP_CLIENT_ID`(공개, SDK용) + `NAVER_MAP_CLIENT_ID`/`NAVER_MAP_CLIENT_SECRET`(서버 전용, Geocoding REST API 인증용)로 교체
- `src/lib/naver-loader.ts` 신설 — Web Dynamic Map JS SDK(`ncpKeyId` 파라미터) 지연 로더. 기존 `kakao-loader.ts`가 지오코딩 서비스 모듈까지 같이 로드했던 것과 달리, 지오코딩은 서버로 옮겨서 이 로더는 지도 표시 전용
- `src/app/api/geocode`, `src/app/api/reverse-geocode` 신설 — Naver Geocoding/Reverse Geocoding REST API는 Client Secret이 필요해 브라우저에서 직접 호출 불가능. 어드민 폼이 기존엔 카카오 SDK로 클라이언트에서 바로 지오코딩하던 걸, 서버 API 라우트를 거치는 구조로 변경(아키텍처상 더 안전해진 부분)
- `src/components/KakaoMap.tsx` → `src/components/NaverMap.tsx` 전면 이식: `LatLng`/`LatLngBounds`(빈 생성 불가라 첫 좌표로 초기화 후 `extend`)/`fitBounds`, `CustomOverlay` → `Marker`(HTML `icon.content`), `Circle`/`Polyline`/`Polygon`(지역 경계선), 클릭 판정은 지도 click 이벤트 + `getProjection().fromCoordToOffset()` 픽셀 거리 계산 방식을 그대로 유지(카카오에서 마커 자체 클릭 판정이 드래그 판정과 얽혀 불안정했던 문제를 피하려고 원래 택한 방식이라, 검증된 동작을 굳이 바꾸지 않음), `relayout()` → `autoResize()`
- `src/components/admin/LocationMapPicker.tsx` 동일 방식으로 이식(좌표 클릭 지정 + 기존 포인트 회색 점 표시)
- `LocationForm.tsx`/`LocationDetailsEditor.tsx`: 클라이언트 카카오 지오코더 호출을 `/api/geocode`, `/api/reverse-geocode` fetch 호출로 교체
- `MapScreen.tsx` import 교체, 옛 `KakaoMap.tsx`/`kakao-loader.ts` 삭제
- CLAUDE.md·기획서의 지도 스택 설명을 Naver Maps 기준으로 갱신(전환 사유 포함)
- `npx tsc --noEmit`, `eslint` 통과 확인 (기존에 있던 무관한 lint 에러 2건 제외)

### 4. 실기기 확인 중 발견한 이슈
- 초기 줌 레벨을 카카오 level→네이버 zoom 근사 변환값으로 넣었는데, 실제로는 지도 생성 직후 `fitBounds()`가 마커 범위에 맞춰 다시 계산하므로 초기값 자체는 크게 중요하지 않음(원래 카카오 코드도 동일 구조)
- 사용자가 "카카오 땐 보이던 버스정류장 마커가 안 보인다"고 제보 — 최대 줌으로 확대해도 안 나타나는 걸 스크린샷으로 확인. 조사 결과 Naver Web Dynamic Map JS API의 공식 레이어 종류(자전거도로/교통정보/거리뷰영역/지적편집도)엔 대중교통 POI 토글이 없어, 기본 지도 스타일 자체의 제약으로 판단. 코드로 해결 가능한 부분이 아니고, 이번 전환 목적(도로 최신성)과도 무관해 사용자가 패스하기로 함
