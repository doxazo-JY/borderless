# 데일리 노트 — 2026.08.08

## 오늘 요약 (공유용)

소속 선택 화면이 "기능만 담은 초안 같다"는 지적에서 출발해, 이 화면과 지도 화면에 "그을린 양피지" 톤 배경을 실험한 날. 처음엔 도트 그리드+그림자 정도로 살짝만 손봤다가 "그냥 모눈종이로 바뀐 느낌"이라는 반려를 받았고, 사용자가 GPT로 따로 만들어본 트레저맵 톤(세피아, 색 하드코딩)을 보여줘서 그 방향성 자체는 가져오되 디자인 토큰과 분리된 로컬 변수 위에서 다시 만들었다. 배경 얼룩은 CSS `radial-gradient` 타원으로 시작했다가 "도장 찍어놓은 것 같다"는 지적을 받고, feTurbulence 노이즈 자체를 얼룩 모양으로 쓰는 방식(`ParchmentStains.tsx`)으로 전면 교체했다. 그을린 테두리(`ParchmentBurn.tsx`)는 SVG가 기본 크기(300×150)로 쪼그라드는 버그를 겪고 `width`/`height` 속성을 직접 박아 고쳤고, 두께·위치를 여러 차례 되돌리고 다시 조정했다. 팀 컬러 4색을 그대로 쓴 루트/X마크 장식은 "장난감 지도 같다"는 반려를 받아 낡은 잉크 톤 하나로 통일했고, X마크는 뾰족한 붓모양이 "수리검 같다"는 지적을 받은 뒤 사용자가 준 실제 CSS 붓터치 레퍼런스를 SVG로 옮겨 다시 만들었다. 이 톤을 지도 화면까지 넓히면서 헤더가 테두리와 겹치는 문제를 겪었고, 안쪽 padding을 늘리는 대신 테두리 자체를 화면 끝으로 미는 방식(`insetPercent`)으로 해결했다. 지도 화면의 하위 패널(위치 상세/숙소/대화 주제/빈 안내)에도 옅은 버전을 얹어 통일했다. 그 과정에서 안 쓰던 인벤토리 화면이 실제로는 라우트가 살아있는 걸 발견해 완전히 삭제했다.

## 오늘 한 일

### 1. 소속 선택 화면 — 1차 시도(도트 그리드)와 반려

- 배경을 단색 종이에서 옅은 도트 그리드로, 팀 버튼에 팀 컬러 배경 틴트+그림자를 추가, `BrandMark.tsx`(경계선을 넘는 점선 루트 모티프) 신설
- 사용자 피드백: "그냥 민무늬를 약간 모눈종이로 바꾼 느낌" — 표면 질감만 건드렸지 "장면"을 못 만들었다는 지적

### 2. GPT 트레저맵 실험 참고 → 토큰 위에서 재구성

- 사용자가 GPT와 별도로 만들어본 세피아 트레저맵 배경(코스트라인·나침반·X마크·아일랜드 등, 색 전부 하드코딩)을 공유
- 같은 "장면감"은 가져가되, 하드코딩 색과 세리프 폰트 등 기존 디자인 언어(label-tech 모노스페이스, `--color-*` 토큰)와 어긋나는 부분은 다 걷어내고 재구성하기로 결정
- `MapDecoration.tsx` 신설: 화면 가장자리에서 버튼 쪽으로 모이는 점선 루트 4개 + 팀 컬러 핀, feTurbulence(`sketchy-fine`/`sketchy-coarse` 필터)로 선을 흔들어 손그림 느낌
- 핀 크기를 사용자 요청으로 0.6 → 0.2 → 0.32로 세 차례 조정
- 나침반·좌표 라벨을 화면 모서리에 추가했다가, "굳이 필요 없다"는 피드백으로 완전히 제거

### 3. 배경을 세피아 양피지로 전환, 얼룩 방식 재작업

- `.route-map` 클래스에 로컬 변수(`--parchment-base/mid/dark`)로 세피아 팔레트 도입 — 전역 토큰은 안 건드림(다른 화면과 톤이 갈리지 않게)
- 얼룩(foxing)을 CSS `radial-gradient` 타원 여러 개로 시작 → "너무 납작한 원 그 자체, 도형을 삽입해놓은 듯" 지적
- `ParchmentStains.tsx` 신설: feTurbulence 노이즈를 `feColorMatrix`(RGB 평균→알파)+`feComponentTransfer`(gamma로 중간값 깎기)+`feFlood`+`feComposite`로 가공해 노이즈 자체를 얼룩 모양·진하기로 사용. 크기·색이 다른 3겹을 `mix-blend-mode: multiply`로 겹침
- 색 진하기, gamma 지수(얼룩 개수/크기)를 여러 차례 왕복 조정 — "너무 심해졌다" → 이전 값으로 롤백 → "중간 정도로" 재조정

### 4. 그을린 테두리 — SVG 크기 버그와 두께/위치 조정

- `ParchmentBurn.tsx` 신설: 두꺼운 `<rect>` 테두리에 feTurbulence 기반 `feDisplacementMap`을 적용해 울퉁불퉁하게. 서로 다른 노이즈 시드의 두 겹을 겹쳐서 한 자리에서 매끈해지는 걸 방지
- "테두리에 기본 바탕색이 조금씩 보인다"는 지적에 solid border를 밑에 깔았다가 "잘못 이해한 것 같다"는 피드백으로 되돌림
- "네모 테두리(각져 보이는 겹)를 없애고 울퉁불퉁한 겹만 넓혀달라" → 두꺼운 겹 제거, 얇은 겹 두께만 확대 → 다시 "이때로 되돌려봐" 요청으로 두 겹 버전으로 롤백 → 화면 가장자리에 진짜 각진 사각형이 보인다는 지적 → 원인 파악: 폭이 넓은 겹은 흔들림이 상대적으로 작아 보여 각지게 읽힘 → 결국 `#4A2F18` 색의 얇은 겹을 지우고 서로 다른 시드의 두 겹(`#241206`/`#3a2410`)으로 재구성
- "테두리 관련된 거 싹 없애봐" → 컴포넌트·CSS·import 전부 제거 → "울퉁불퉁 선만 2겹으로 추가해줘" → 다시 만듦
- 지도 화면 확장 시 SVG가 기본 크기(300×150)로 렌더링되는 버그 발견 — `<svg>`에 `width="100%" height="100%"`를 CSS 클래스뿐 아니라 속성으로도 직접 지정해 해결
- 두께를 prop화(`outerWidth`/`innerWidth`, 기본값은 소속 선택 화면 기준) + `insetPercent`(테두리가 가장자리에서 얼마나 안쪽에서 시작할지)로 확장해, 지도 화면에서는 더 얇고 더 바깥쪽에 배치되도록 함

### 5. X마크·잉크 튀김 — 수리검 사고와 붓터치 레퍼런스 반영

- 팀 컬러 핀 드롭 대신 "X marks the spot" 모티프로 교체(팀 컬러 유지) → "장난감 지도 같다" 지적으로 낡은 잉크 톤 하나로 통일
- 뾰족한 양끝의 렌즈형 붓자국(`BRUSH_STROKE`)으로 처음 만들었다가 "수리검 같다"는 지적 — 양끝을 뭉툭하게 수정
- 사용자가 실제 CSS 붓터치 레퍼런스(clip-path 다각형 + 그라디언트 페이드)를 제공 → 그 다각형 좌표를 그대로 SVG로 옮기고(`BRUSH_STROKE_JAGGED`), 양 끝이 옅어지는 `linearGradient`로 채움
- 두 획 색이 "너무 따로 논다"는 지적으로 톤을 좁힘(`#8f431e`/`#663018` → `#7c3c1e`/`#6e351a`)
- 잉크 튀김 점: 처음엔 마크마다 똑같은 배치 4개 → "패턴 같다" → 마크별로 다른 배치(개수도 1~5개로 다양화) → "여전히 어색하다, 튄 건 우연이니 1개나 0개가 맞다" → 최종적으로 마크당 0~1개로 정리

### 6. 경로선을 잉크 자국처럼

- 참고 이미지(길쭉한 점선 자국)를 보고 `stroke-dasharray`를 조정해 둥근 캡의 길쭉한 다시 모양으로
- 두께·간격을 여러 차례 조정(5/얇게 3.2/더 얇게 1.5)
- `ink-mottle` SVG 필터(feTurbulence+feColorMatrix+feComponentTransfer+feComposite)를 추가해 점선 하나 안에서도 농도가 불규칙하게 흔들리도록 함

### 7. 지도 화면으로 확장

- `MapScreen.tsx`의 `<main>` 배경을 `bg-paper`에서 `.route-map`(양피지)으로 교체, `ParchmentStains`+`ParchmentBurn`을 배경에 추가
- 헤더가 화면 가장자리에 바짝 붙어있어 테두리와 겹치는 문제 — 내부 콘텐츠를 padding wrapper로 감싸고, `ParchmentBurn`의 두께를 얇게(outerWidth 54→14, innerWidth 34→9), `insetPercent`로 테두리를 화면 끝 쪽으로 밀어서 해결(단순히 padding만 늘리는 대신 테두리 위치 자체를 옮기는 쪽으로 최종 결정)
- 지도 화면과 함께 뜨는 하위 패널(`LocationPanel`/`PensionPanel`/`ConversationTopicPanel`, 포인트 미선택 시 빈 안내 패널)에도 `.parchment-panel`(배경보다 한 톤 밝은 베이스 + 같은 섬유선 결) + 옅은 `ParchmentStains`(intensity 0.4)를 적용
- `ParchmentStains`에 `idPrefix`/`intensity` prop을 추가해 한 페이지에 여러 번 써도 SVG filter id가 안 겹치고, 패널마다 진하기를 다르게 줄 수 있게 함
