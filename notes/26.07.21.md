# 데일리 노트 — 2026.07.21

## 오늘 요약 (공유용)

기능적으로 가장 큰 하루. 처음엔 답사 전 리허설용 테스트 사진 판정 기준을 다듬는 작업으로 시작했다가, 재료 모델에서 아무 로직도 안 읽던 죽은 필드를 발견해 정리했고, 거기서 이어서 미션 타입을 4번째(퀴즈)까지 늘렸다. 어드민 쪽은 지급확정/대시보드/제출영상 세 페이지로 흩어져 있던 걸 대시보드 하나로 합치고 "전체 초기화" 버튼을 추가했으며, 참가자 이름 처리 방식은 하루 안에 한 번 크게 뒤집었다(참가자가 매번 입력 → 어드민이 미리 등록). 그 과정에서 "dev 서버 재시작 안 하면 방금 바꾼 스키마/코드가 반영 안 된 것처럼 보인다"는 패턴을 세 번 넘게 겪었고, 어드민 그리드 레이아웃 폭은 좁다/납작하다를 오가며 여러 번 조정했다.

## 오늘 한 일

### 1. 테스트 사진 판정 기준 다듬기 (리허설 준비)

- 사용자가 새로 찍은 테스트 사진 5장(아파트 외벽, 시민게시판, 이마트 배너, 버스노선도, 버스정류장 표지판)에 대해 사용 가능 여부를 검토하고, 각각 judgePrompt를 작성함. 처음엔 "핵심 요소 + 무시해도 되는 요소"만 한두 문장으로 짧게 썼는데, 사용자가 "예전 것보다 디테일이 부족하다"고 지적 — [notes/26.07.20.md](26.07.20.md)에서 이미 정립했던 "장면 설명 문장 → 랜드마크 번호 목록 → 2개 이상 일치 시 통과 / 완전히 다른 경우만 불합격" 3단 구조로 다시 씀.
- 이어서 "2개 이상 일치"라는 임계값 자체가 적절한지 논의함. 버스정류장 표지판·시민게시판처럼 인천 시내에 표준적으로 깔린 시설물은, 정작 그 지점을 특정하는 고유 요소(도로명+번호 등)를 안 보고도 일반적인 생김새 요소 2개만 겹치면 통과할 수 있다는 오탐 위험을 짚음 — 반대로 "5개 중 4개 일치"처럼 너무 엄격하게 가면, 실외에서 급하게 찍는 사진 특성상(각도/역광/프레임 잘림) 오히려 놓치는 게 많아지고 이 앱이 이미 "재시도 무제한 + 도움 요청이 안전망이 아니라 주력 백업"일 정도로 오판정에 관대한 설계 철학을 갖고 있다는 점과 충돌한다고 판단. 최종적으로 **"고유 식별 텍스트(숫자/ID)는 필수 + 나머지 요소 중 과반 추가 일치"**로 절충함.
- 이 형식을 이전에 검토했던 다른 3장(아파트 정문·emart 사거리·상가 간판)에도 소급 적용 — 여기서도 "emart 로고"처럼 전국 어디나 있는 체인 요소는 고유 식별자가 될 수 없고, 배경의 특정 병원 간판처럼 그 자리에만 있는 게 진짜 식별자라는 걸 다시 짚음.

### 2. 재료 모델 단순화 + 퀴즈 미션 타입 추가 (`0c7863b`)

- 판정 기준을 다듬다가 DB에 저장된 실제 판정 프롬프트를 확인하려던 중, `Ingredient`의 `category`/`variant`/`isBase` 필드가 어드민 화면 표시에만 쓰이고 게임 로직 어디에서도 안 읽힌다는 걸 코드로 직접 확인함. `variant`도 마찬가지로 `name`과 항상 같이 붙여서만 쓰였음("떡" + variant "치즈떡" → 화면엔 항상 "떡(치즈떡)"). 사용자가 "그럼 처음부터 name에 다 넣으면 되는 거 아니냐"고 지적 — 세 필드 다 제거하고 `name` 하나로 통합, 기존 데이터는 마이그레이션으로 `name || '(' || variant || ')'` 형태로 합침.
- 이 과정에서 **"dev 서버가 스키마 변경 전 Prisma Client를 그대로 물고 있어서 `Ingredient.category` 컬럼이 없다는 500 에러가 난다"**는 문제를 처음 겪음 — 이후 이 세션에서 두 번 더 반복되는 패턴의 시작.
- 이어서 미션 타입을 말씀/찬양/기도 3개에서 4번째(퀴즈, `PUZZLE`)로 확장. 처음엔 "게임/미션" 정도로 막연하게 시작했다가, 완료 방식을 놓고 논의 — 기존 3개처럼 영상 업로드로 갈지, 텍스트 정답 제출로 갈지 결정해야 했고 **영상 업로드 없이 정답 텍스트 제출로 완료**하는 쪽으로 정함. `Mission.answer`(쉼표로 여러 정답), `Submission.answerText`/`answerCorrect` 추가, 정답 비교는 공백 전부 제거 + 소문자 변환으로 정규화(예: "사랑한다 말하시네"와 "사랑한다말하시네"를 같은 답으로 인식).
- 타입 이름을 "문제"로 시작했다가 "이슈/말썽"이라는 뜻과 헷갈릴 수 있다는 지적에 "퀴즈"로 변경. 이후 "퀴즈 질문 자체가 사진(이모지 조합 등)으로 구성될 수도 있지 않냐"는 요청으로 `Mission.imageUrl` 추가, PASS 카드에 미션 사진을 같이 보여주도록 함(기존 위치 기준 사진 업로드와 같은 패턴 재사용, [src/components/admin/MissionPhotoUpload.tsx](../src/components/admin/MissionPhotoUpload.tsx) 신규).
- 미션에 사진 첨부 기능을 넣으면서 어드민 미션 목록 CSS 그리드가 깨지는 버그가 생김 — 수정 폼에 입력칸이 늘어나면서(내용+정답 두 칸) 그 폼이 속한 그리드 열이 폭을 무한정 요구했고, 그리드가 다른 열에서 폭을 뺏어오면서 옆 미션 카드가 한 글자씩 세로로 쌓이는 현상이 발생. `MissionEditor` 수정 폼에 `w-full`을 줘서 고정.
- 지급확정/대시보드/제출영상으로 흩어져 있던 어드민 페이지 3개를 대시보드 하나로 통합. "포인트별 잔여 캡"을 "포인트별 현황"으로 확장해서, 통과한 그룹별로 제출 사진·영상(또는 퀴즈 정답)·지급확정 버튼·초기화 버튼을 카드 안에 다 넣음. 답사/리허설 중 쌓인 테스트 데이터를 한 번에 지우는 "전체 초기화" 버튼도 추가(확인 대화상자 필수).
- 지도 마커에 지역 알파벳(A/B/C/D)을 상태 기호와 같이 표시(예: `A✓`, `B▶`)해서 지역 구분이 안 되던 문제 해결. 어드민 미션/포인트 목록에 `orderBy` 없이 조회하던 걸 타입/활성여부 기준으로 정렬해서, 수정할 때마다 저장 위치가 바뀌며 목록 순서가 흔들리던 문제도 고침.

### 3. 도움 요청 이름/메시지, 참가자 이름 처리 방식 뒤집기 (`3c1e653`)

- 도움 요청 버튼이 위치/사유 정보 없이 그냥 "도움 요청" 알림만 보내던 걸, 누르면 문제 설명을 적는 텍스트창이 펼쳐지도록 바꿈(`HelpRequest.message` 추가).
- 어느 팀의 누구에게 문제가 생겼는지 알아야 연락할 수 있다는 요구로, **처음엔 팀/조 선택 화면에서 조원 2명 이름을 매번 입력받아 쿠키에 저장**하는 방식으로 구현(`TeamGroupSelect.tsx` 클라이언트 컴포넌트 신규, `selectGroup`에 이름 검증 추가). 도움 요청 시 그 쿠키 값을 `HelpRequest.requesterName`으로 스냅샷.
- 그런데 사용자가 팀 선택 잠금을 해제해두고 반복 테스트하면서 "매번 이름을 다시 쳐야 해서 귀찮다"고 피드백 — **같은 날 안에 설계를 뒤집음**. 참가자 쪽 이름 입력을 완전히 제거하고, 대신 어드민 설정 화면에서 조마다 조원1/조원2 이름을 미리 등록해두는 방식으로 전환(`Group.memberName1`/`memberName2` 추가). 참가자는 다시 원래처럼 그룹 버튼 한 번 클릭으로 끝나고, 도움 요청 시 그 그룹에 등록된 이름을 그대로 스냅샷. `TeamGroupSelect.tsx`와 참가자 이름 쿠키 관련 코드는 전부 삭제.
- `HelpButton`이 서버가 4xx/5xx를 응답해도 "요청 완료!"로 표시하던 버그를 발견 — `fetch()`는 에러 상태코드에서 예외를 안 던지므로 `res.ok`를 직접 확인하도록 수정. 이 버그는 위 "dev 서버가 스키마 변경 전 상태를 물고 있는" 문제(이번엔 `HelpRequest.message`/`requesterName` 컬럼)가 겹쳐서 실제로는 저장이 실패했는데 성공한 것처럼 보였던 사례.
- 지도 마커 선택 표시를 처음엔 오렌지색 링(box-shadow)으로 시도했는데 "색이 안 어울려서 어색하다"는 피드백으로, 마커 자체의 상태 색을 25% 어둡게 낮추는 방식으로 교체(새 색 추가 없이 크기+명도만 변경). 범례도 색 점 대신 실제 핀 모양(알파벳+기호)을 축소해서 보여주도록 함.
- 어드민 목록/그리드를 고정 컬럼 수(`sm:grid-cols-2 lg:grid-cols-3` 등) 대신 `auto-fit minmax()` 트랙으로 전환 — 항목 개수가 컬럼 수보다 적을 때 그리드가 나머지 칸을 비워두고 항목을 왼쪽에 몰아넣어 "가운데만 좁게" 보이던 문제(도움요청/대시보드/설정 페이지 공통) 해결.
- 대시보드 "전체 초기화"가 `HelpRequest`도 같이 지우도록 확장. 참가자 이름은 이제 DB(Group)에 있어서 이 버튼으로도 안 지워지는 게 아니라 오히려 **의도적으로 지워지지 않게** 뒀다(리허설 중 쌓인 제출/요청 기록만 정리 대상).

### 4. 지도/어드민 폴리시, 잠금 상태 홈 리다이렉트 (`0fa15e5`)

- 지금 갈 수 없는 지역(차례 아님, 또는 같은 지역의 다른 포인트에서 이미 통과해서 더 볼 필요 없는 포인트)의 마커를 새 색 없이 투명도만 낮춰서 흐리게 표시 — "지금 차례인 지역의 열린 포인트만 상대적으로 도드라지게 하고 싶다"는 요청을, 색 팔레트를 늘리지 않는 선에서 구현.
- 어드민 페이지 폭을 두고 여러 번 왔다갔다함: `max-w-7xl`(가운데 정렬) → 넓은 PC 모니터에서 양옆 여백 낭비 지적 → `w-full`(꽉 채움) → 이번엔 카드가 너무 납작하게 늘어난다는 지적 → 결국 `max-w-[1600px]`로 중간 지점을 찾음. 대시보드 "포인트별 현황"은 사진/영상까지 들어가는 카드라 auto-fit이 만들어내는 좁은 열(260px)로는 부족해서, 여기만 고정 4열로 바꿈.
- 미션/포인트 카드 텍스트가 `break-words`/`truncate`로 단어 중간에서 끊기거나 "..."로 잘리던 걸 `break-keep`(어절 단위 줄바꿈)으로 교체. 수정/삭제/사진교체 액션 링크가 제목 옆에 붙어서 줄바꿈될 때 같이 밀리던 걸, 카드 하단에 구분선을 두고 별도 줄로 분리.
- 이미 팀/조를 선택하고 잠긴 기기가 "/"(팀 선택 화면)에 다시 들어오면(뒤로가기 등) 곧장 `/map`으로 리다이렉트하도록 추가 — 잠긴 상태에서 선택 화면에 머물 이유가 없다는 요청.

### 5. 정원 마감 로직 재확인, GPT 모델 비용 검토

- "이미 2팀이 완료한 포인트인데 세 번째 팀이 사진을 올렸더니 AI 판정까지 통과하고 미션이 보였다"는 버그 제보를 받음. `/api/submissions/route.ts`는 원래도 캡 확인(`claimedCount >= capacity`)을 AI 호출보다 먼저 하도록 돼 있어 코드상으로는 이런 일이 불가능한 구조인데, 재현 당시 데이터를 사용자가 이미 "전체 초기화"로 지운 뒤라 DB로 직접 확인은 못 함. 이후 재현 없이 "갑자기 또 되네요"로 일단락 — 앞서 반복된 dev 서버 미갱신 패턴의 네 번째 사례일 가능성이 높다고 보고 있음(확정은 아님). 마감 안내 문구는 "이미 마감된 장소입니다. 다른 장소로 이동해주세요."로 다듬어둠.
- 사용자가 OpenAI 플랫폼 사용량($0.39/$120)을 보여주며 더 가벼운 모델로 바꿔 비용을 줄이는 게 어떨지 물음. 처음엔 `gpt-4.1-mini`를 막연히 추천했는데, 실제로 웹 검색으로 가격을 확인해보니 **`gpt-4.1-mini`가 오히려 현재 쓰는 `gpt-4o-mini`보다 약 2.7배 비쌌음**(입력 $0.40 vs $0.15, 출력 $1.60 vs $0.60/1M 토큰) — 잘못된 추천이었다고 정정. 비용을 줄이려면 `gpt-4.1-nano`(입력 $0.10, 출력 $0.40)가 맞는 방향이지만, 현재 사용량이 무료 크레딧($5)도 안 채운 수준이라 당장 바꿀 실익은 적다고 판단, 그대로 유지하기로 함.
